# Как опубликовать обновление MIRA

Архив `MIRA_RevA_Distributed_Power_20261028.zip` содержит полный проект, обновлённые документы, комментарии к заданиям и `MIRA_update.bundle` с готовой Git-веткой. Bundle переносит изменения обеих плат и документов вместе. Сам ZIP не нужно класть внутрь Git-репозитория.

## Рекомендуемый способ

1. Распакуйте архив. Ниже предполагается папка `~/Downloads/MIRA_RevA_Distributed_Power`; если она другая, подставьте её путь.
2. Сохраните и закоммитьте свои текущие изменения в `/home/dima54/Projects/mira`, если они есть. Скрипт остановится при незакоммиченных файлах и ничего не сотрёт.
3. Подготовьте отдельную ветку:

   ```bash
   bash ~/Downloads/MIRA_RevA_Distributed_Power/prepare-github-branch.sh /home/dima54/Projects/mira
   ```

   Скрипт проверяет репозиторий `max-talanov/mira`, загружает сведения из `origin`, проверяет bundle и импортирует ветку `mira-update-20261028`. Исходная `main` остаётся на своём коммите. Требуется существующая общая основа `24b4428`; если её нет или ветка с таким именем уже содержит другие изменения, скрипт безопасно остановится.

4. Просмотрите `git log -5 --oneline` и `git diff --stat origin/main...HEAD`, затем отправьте ветку:

   ```bash
   cd /home/dima54/Projects/mira
   git push -u origin mira-update-20261028
   ```

5. Откройте [сравнение с main](https://github.com/max-talanov/mira/compare/main...mira-update-20261028), создайте Pull Request и проверьте список изменений. Если GitHub показывает конфликт с более новой `main`, сначала разрешите его; не используйте принудительную отправку. Для merge нужен разрешённый репозиторием способ и права доступа.
6. Вставьте готовые комментарии из `docs/pcb-preparation/task-comments/task-1.md` и `task-2.md` в соответствующие задания. Их номера не определены; не путайте порядковый номер задания с номером Issue.

Заголовок PR: **Update distributed power interface and task 1/2 documentation**.

Описание PR:

> Обновляет обе схемы MIRA до распределённого межплатного питания: семь местных силовых вводов и отдельный служебный интерфейс, восемь пар Samtec, положительный sense CORE и TEN 30-2413WIN на N15. Синхронизирует документы по заданиям 1/2 и XLSX/JSON с запасом 30% к предварительным пиковым нагрузкам. Исходные отчёты и расчёт сохранены в истории.
>
> Проверки схем: 118 сопряжённых контактов, 6686 сохранённых подключений вне заменённых разъёмов, ERC 0/0/0 на обеих платах под опубликованным набором правил. Расчёт: 220 независимых численных сверок, проверка изменения входных данных, отсутствие ошибок формул в XLSX.
>
> Остаются открыты XPE/нагрузка матрицы, N15 startup/OCP, распределение IO3V3, VTT/VREF, компоновка PCB и тепловая/динамическая квалификация. Эта версия не объявляет готовность к производству.

## Если нужен ZIP именно на GitHub

После merge откройте **Releases → Draft a new release**, выберите согласованный тег/коммит и прикрепите ZIP как файл релиза. Это отдельное действие от обновления исходников: загрузка ZIP сама по себе не обновит `hardware/` и `docs/`. Имя релиза и тег здесь не назначены.

Документация GitHub: [добавление файлов и отправка ветки](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository). Через сайт можно загружать до 100 файлов за один раз; полный проект удобнее передать Git-веткой. Фактическая отправка, публикация PR/Release и комментариев выполняются в вашем авторизованном GitHub-сеансе.
