# Допустимость сигналов при отключённом питании — 2026-10-30

**Пункт открыт.** В схему внесены две цифровые защиты; обнаруженные аналоговые пути подпитки ещё не устранены. ERC не проверяет powered-off поведение микросхем.

База: `MIRA_RevA_Fault_Hardware_20261029.zip`, SHA-256 `f84f1b0a319177192a749f775ca5614ba37a12dc12c30aebc03a7cedb06dcb3f`. Анализ выполнен по нативным KiCad netlist обеих плат и указанным ниже спецификациям. Результат — схемная ревизия, не разрешение на производство.

## Что изменено

Новый лист Power `5500_AON_HOST_INPUT_ISOLATION`: U5501/U5502 — Nexperia `74LVC1G17GV,125`, C5501/C5502 — 100 nF, R5501/R5502/R5503 — 100 kΩ. Всего 7 компонентов. На прежних компонентах изменены только U2602.10, R3305.2, R3306.1. Плата Control электрически не изменена.

| Линия | До | После |
|---|---|---|
| Host reset | HOST_RESET_N непосредственно на U2602.10 | HOST_RESET_N → U5501(AON) → HOST_RESET_AON_N → U2602.10 |
| Приём UART | HOST_UART_TX → 1k → PM_UART_RX | HOST_UART_TX → 1k → HOST_UART_TX_RAW → U5502(AON) → PM_UART_RX |

R3306 остаётся подтяжкой raw-входа к GND; R5503 удерживает PM-вход LOW при отключённом выходе. U5501 не меняет электрическую линию сброса STM32 host и не заменяет открытый сток U5405. При пропадании питания / BREAK UART LOW не считается валидным сообщением; прошивка должна заново синхронизировать кадры.

Для выбранного Nexperia MPN: вход 0…5.5 В; Ioff при VCC=0 максимум ±2 µA, входная утечка максимум ±1 µA по таблице 10 при оговорённых тестовых условиях. Это не гарантия нулевого тока. Новый входной pulldown с существующим reset-pullup 10k даёт номинально 3.0 В при SYS3V3=3.3 В. Общая земля обязательна. При промежуточном AON ниже рабочего диапазона логика не квалифицирована; прежний supervisor удерживает разрешения. Учесть дополнительно **2 mA и 0.2 µF на AON**; это проектный запас, не измеренный расход. Существующий расчёт бюджета остаётся исторической базой с этой добавкой.

## Найденные цепи

### SIG-01 — ИСПРАВЛЕНО ПО СХЕМЕ

**HOST_RESET_N → U2602.10**. Условие: SYS3V3 есть, AON=0.

У HCS21 вход ограничен собственной VCC. Новый U5501 принимает HOST_RESET_N и передаёт HOST_RESET_AON_N; питание AON, Ioff. Host NRST и открытый сток U5405 остаются на исходной линии.

Основание: LVC17; HCS21.

### SIG-02 — УСИЛЕНА ЗАЩИТА ПО СХЕМЕ

**HOST_UART_TX → R3305 → PM PD9**. Условие: SYS3V3 есть, AON=0.

U5502 отделяет вход PM от host. R3305=1k и R3306=100k остаются перед буфером; R5503=100k задаёт выход LOW. Это явная защита Ioff; прежний путь через STM32 не объявлен доказанной аварией лишь по отсутствию питания.

Основание: LVC17.

### SIG-03 — ОТКРЫТО — ПРИОРИТЕТ 1

**BUS24 → R3501/R3502 → D3501 → AON; остальные измерители**. Условие: Вход 24 В или другая шина есть, AON=0.

Верхние диоды BAT54S подключены к AON. Для номинальных 24 В, 150k/10k и принятого Vf=0.25 В ток в AON ≈(24−0.25)/150k−0.25/10k=133 µA. Это оценка пути, не измерение и не точный Vf. Для 30 В ≈173 µA. Резисторы ограничивают ток, но не устраняют подпитку. OE мультиплексора этот путь не разрывает.

Основание: Нативные сети R3501–R3503, D3501, U3902.

### SIG-04 — ОТКРЫТО — ПРИОРИТЕТ 1

**VTT → R3304 → ADC_VTT → D3301 → AON**. Условие: VTT сохраняется, AON=0.

Отдельный вход PM обходит U3902. При VTT=0.675 В и том же условном Vf=0.25 В ток через 1k ≈425 µA. В ревизии 5500 эта аналоговая цепь не изменена.

Основание: Нативные сети R3304, D3301, U2401.19.

### SIG-05 — ОТКРЫТО — ПРИОРИТЕТ 2

**IO3V3 → адреса/IN/EN аналоговых ключей**. Условие: P15=0 при живой IO3V3.

Инвентаризация: 19×ADG5412, 9×ADG5408, 3×ADG5434, 1×ADG5409, 1×ADG1208. На проверенных ADG5412/5408/1208 верхний предел связан с VDD+0.3 В; допускаемый ток clamp не означает отсутствия подпитки. U2100.2 и U1902.2 постоянно на IO3V3. MATRIX_PERMIT=0 не обнуляет все адреса и EN. Для ADG5434 требуется отдельная полная проверка спецификации; он включён в инвентаризацию, а не объявлен проверенным.

Основание: ADG5412; ADG5408; ADG1208.

### SIG-06 — ОТКРЫТО — ПРИОРИТЕТ 2

**40 выходов AD5676R → входы OPA4192**. Условие: ANA5 жива, P15 исчезла, код ЦАП ненулевой.

Нативная сеть содержит 32 BL и 8 service DAC соединений без входной изоляции. Предел общего режима OPAx192 зависит от V−/V+; ESD-цепи ведут к питанию. Загрузка нулевого кода при штатном выключении не покрывает внезапное исчезновение P15.

Основание: OPA192; список exposed-inputs.csv.

### SIG-07 — ОТКРЫТО — ПРИОРИТЕТ 3

**MAT_ADC_REF / THP210 / AD4003**. Условие: P15/REF исчезли, ANA5 ещё есть; либо ANA5 исчезла при живой ±15 В.

У AD4003 цифровая VIO и VDD допускают любой порядок; это само по себе не ошибка. Но IN± ограничены REF+0.4 В: сохранённый выход THP210 при провале REF требует защиты/ограничения. Обратное направление ±15 В → входная резистивная сеть THP210 также требует расчёта; режим PD не убирает ESD-цепи.

Основание: AD4003; THP210.

### SIG-08 — ОТКРЫТО — ПРИОРИТЕТ 3

**MAT_CC_SENSE_BUF / MAT_ILIM_SENSE_BUF → TLV3201**. Условие: IO3V3=0, аналоговые буферы ещё работают.

R2200=49.9k/R2201=10k и R2202=37.4k/R2203=10k уменьшают напряжение и ток, но не изолируют VCC компаратора. По TLV3201 входы имеют диодные clamps к питанию; ограничение 10 mA — предел защиты, а не разрешение подпитывать IO3V3.

Основание: TLV3201.

### SIG-09 — ТРЕБУЕТ ДОПОЛНИТЕЛЬНОЙ КВАЛИФИКАЦИИ

**OPA2991 / INA301; PG/EN; USB; Ethernet PHY/FPGA; SWD**. Условие: Отсутствует одна из шин или подключён внешний источник.

Для закрытия всего пункта нужны пределы тока/напряжения каждого входа при VCC=0 и при частичном питании, включая распад ±15 В по одной полярности. SWD/J3302 допускаются только с адаптером, который воспринимает VTREF как вход и не выдаёт сигналы при VTREF=0. USB data/CC, независимые ядра/VIO и питание от внешнего кабеля здесь не объявлены проверенными.

Основание: Открытый объём проверки.

## Что уже предусмотрено и как трактовать результат

Power U3301 и Control U400/U900/U901 используют Nexperia 74LVC125A с Ioff; U4901, Control U401/U708 используют 74LVC1G17. Эти буферы имеют явную поддержку отключённого питания в пределах спецификации. Это подтверждение выбранных приёмников, не доказательство безопасности всей платы и всех параллельных путей.

AD5676R имеет отдельную VLOGIC=IO3V3: сам факт отсутствия ANA5 не доказывает нарушения цифровых входов. Рекомендуемый порядок производителя: земля, VLOGIC, VDD, затем цифровые сигналы. AD5761R имеет отдельную DVCC: цифровые абсолютные пределы отсчитываются от DVCC. Работоспособность при пропадании аналоговых шин и безопасное состояние выходов отдельно не квалифицированы.

В инвентаризации 19 BAT54S с верхним выводом на AON, включая собственный MON_V_AON и несколько путей OPA2991; это **не 19 независимых доказанных нарушений**. Полный список выводов и сетей: `exposed-inputs.csv` / `.json`. Выходы ЦАП и цифровые входы 33 аналоговых ключей перечислены поштучно.

## Следующая правка схемы

1. **Начать с Power, листов 3300/3400/3500–4000.** Устранить возможность подачи энергии в AON через измерители. Изоляция должна находиться до существующих верхних clamps; защита только общего выхода мультиплексора не помогает. Проверить каждый делитель, ADC_VTT и обе цепи OPA2991 отдельно. Если меняется мультиплексор, требуются одновременно powered-off analog isolation и допустимость цифровых входов; одно свойство не заменяет другое.
2. Затем Control: адреса/IN/EN всех аналоговых ключей, включая постоянно высокий EN, и 40 DAC→OPA входов. Выбор новых ключей должен учитывать обе аналоговые стороны, одну отсутствующую полярность питания, Ron, утечку, ёмкость, заряд инжекции и время установления. Простая массовая замена ADG без этих проверок в эту ревизию не включена.
3. Защитить цепочку REF/ADC/FDA и компаратор. Пересчитать сопротивления, шум и установление; простая добавка резистора может ограничить ток, но не исключает подпитку.
4. Проверить оставшиеся PG/EN, мониторинг тока, USB, интерфейсы с отдельным ядром/VIO и внешний debug. После этого заново проверить порядок выключения и ограничения прошивки PM.

## Условия закрытия пункта

Для каждой границы питания должны быть зафиксированы передатчик, приёмник, разрешённое напряжение при VCC=0, худший ток во вход/шину и поведение при исчезновении одной шины. Absolute maximum, ограничение clamp-тока и логический запрет матрицы не считаются доказательством отсутствия обратного питания.

После схемной правки испытать: (1) холодный запуск с 18/24/30 В и не поднявшейся AON; (2) AON=0 при остаточной SYS/IO/VTT; (3) P15=0 и отдельно N15=0 при ненулевых DAC-кодах и сохранённых адресах; (4) провал REF при ANA5 и обратное сочетание; (5) IO3V3=0 при активной аналоговой части; (6) внешние кабели и debugger; (7) повторный запуск после каждого случая. Измерить токи и подъём выключенных шин, фронты RESET/PG/EN, уровни опасных выходов и необходимость нового ARM. Начинать с ограничением тока; подтверждённые незащищённые входы не испытывать прямым подключением полного сигнала до устранения проблемы. Критерии тока берутся из конкретных datasheet и системного бюджета выключенной шины, а не из произвольного общего порога.

## Проверка этой ревизии

`python3 scripts/verify_unpowered_signals.py` проверяет новые выводы, точные MPN/корпуса, ровно 7 добавленных компонентов, ровно 3 изменения прежних выводов и неизменность всех остальных сетей обеих плат. Исторические baselines не заменены новым результатом: обратное отображение допускает только явно перечисленные изменения. Повторены существующие startup, sequencing, fault hardware, fault scenarios, high-load и connector/ERC проверки. Power — 55 активных листов, Control — 32. KiCad CLI 10.0.8: 0 ERC errors / 0 warnings / 0 exclusions; два прежних стилевых правила остаются отключены. Протоколы находятся рядом с исходными проверками и в `validation.json`.

**Прошивка не реализована; PCB не переразведена; измерений на плате не было.** Все выводы о паразитном питании — анализ схемы и спецификаций, не результаты стенда.
