# FPGA: входные данные MIRA.04

**Решение от 30.10.2026: проверка MIG/Vivado отложена по согласованию с пользователем. Вернуться к ней перед трассировкой FPGA ↔ DDR3L на плате Control и до окончательной фиксации распиновки FPGA. По решению пользователя текущая карточка MIRA.04 закрывается как завершённый схемный этап; проверка MIG остаётся незавершённым условием перед трассировкой. Остальные проверки схемы, проектирование Power и независимые участки Control можно продолжать.**

**Статус: NOT_RUN в Vivado/MIG.** Файлы `*_candidate.xdc` — проверенная по схеме карта выводов, но не результат генерации MIG. Они не подтверждают размещение PHY, DRC или timing closure. Tcl подготовлен по UG835 и проверен на разбор; выполнения Vivado в этой среде не было.

## Что запускать

Из этой папки, в окружении с полной Vivado и поддержкой Artix-7:

```bash
vivado -mode batch -source create_io_project.tcl -tclargs /absolute/new/mira_io
vivado -mode gui -source create_mig_workspace.tcl -tclargs /absolute/new/mira_mig
```

Каталог результата должен отсутствовать. Первый сценарий создаёт проект I/O planning и отчёты; второй — проект с **неконфигурированным** MIG IP для настройки в GUI. Обнаружение IP не означает подтверждение платы. Для воспроизводимости сохраните версию Vivado и MIG из установленного каталога IP.

## Настройка MIG и условие завершения

1. Открыть Customize IP для `mira_ddr3l`. Точная FPGA — `xc7a200tfbg484-2`; заказной код — `XC7A200T-2FBG484I`, industrial. Не подменять FBG484 на SBG484.
2. Внести параметры из `mig-settings.json`: DDR3L 1.35 V, один компонент MT41K256M16TW-107:P, x16, 4 Gbit, 400 MHz / 800 MT/s, PHY 4:1; системный и опорный такт 200 MHz. Если точного скоростного варианта нет, создать custom part по даташиту Micron, включая все обязательные тайминги. JSON содержит лишь часть таймингов, он не является custom-part XML.
3. **Disable Controller Chip Select Pin**: CS# U800.L2 подключён к GND. Проверить, что выбранный режим поддержан мастером и в модели памяти CS# тоже заземлён. CL6/CWL5 — целевые значения при tCK=2.5 ns. Внешний VREF 0.675 V на обеих банках; не занимать H18/K14/D15/C20 и не включать внутренний VREF поверх внешнего.
4. Назначить выводы строго по `../../docs/pcb-preparation/digital-interfaces/ddr3l-mig-pin-map.csv`. Использовать фиксированные назначения и Validate. При отклонении мастером сначала исправить схему/карту, затем повторить проверки. Не принимать автоматически предложенную другую распиновку.
5. Для входа LVDS J19/H19 сохранить внешнее согласование и `DIFF_TERM FALSE`. У200 MHz clock один входной буфер: системный и reference clock должны использовать его совместно. Проверить входные уровни с учётом AC coupling и смещения DDR1V35/2. Реальный jitter/сигнал осциллографом ещё не проверены.
6. Сохранить созданные MIG `.prj`, `.xci`, исходники и **сгенерированный** XDC. Открыть Example Design, выполнить synthesis/implementation и сохранить `report_io`, `report_drc`, `report_timing_summary`. Требуются отсутствие нерешённых ошибок назначения/банков/тактов и выполнение ограничений времени.
7. Сопоставить итоговые PACKAGE_PIN с CSV и схемой. После этого интегрировать остальные интерфейсы, выполнить общий implementation и проверить CDC/внешние задержки. Окончательные значения `set_input_delay`/`set_output_delay` зависят от PHY, FIFO, SPI, PCB и RTL; здесь они не выдуманы.

Для готового проекта DDR-ограничения берутся из MIG. `mira_user_io_candidate.xdc` содержит только остальные пользовательские линии. Не подключать одновременно полный `mira_pinout_candidate.xdc` и дублирующий его MIG XDC. `clocks_candidate.xdc` фиксирует плановые частоты; автоматически в I/O проект он не подключается. Режимы RGMII 10/100/1000 и выбранная задержка PHY требуют отдельных timing constraints. Для SPI 25 MHz — проектная цель, не измеренный предел.

Конфигурационные выводы, STARTUPE2/CCLK, CFGBVS и режим загрузки описаны в основной схеме; карта пользовательских портов их не переопределяет. В bank 14 после конфигурации используются dual-purpose выводы USB FIFO. В RTL-проекте необходимо сохранить режим конфигурации и запретить конфликтующее использование этих контактов.

Сверка схемы повторяется из корня репозитория:

```bash
python3 scripts/verify_digital_interfaces.py
```

Нужны Python 3 и `kicad-cli` 10 в PATH. Это статическая проверка, а не замена MIG.
