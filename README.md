# MIRA

Исследовательская платформа для работы с мемристорными кроссбарами: чтение и программирование ячеек, формовка, умножение вектора на матрицу (VMM), спайковые модели.

Карты вставляются в слоты материнской платы. Сокет кроссбара стоит в центре, четыре карты AFE — квадратом вокруг него.

| Плата | Назначение | Проект KiCad |
|---|---|---|
| Mainboard | Материнская плата: слоты, линии каналов к сокету, разъём Zynq-модуля | [`hardware/Mainboard`](hardware/Mainboard/MIRA_Mainboard.kicad_pro) |
| AFE | Карта на 16 каналов с осциллографом тока. В комплекте четыре одинаковые карты | [`hardware/AFE`](hardware/AFE/MIRA_AFE.kicad_pro) |
| Zynq | Модуль с Zynq под сокетом: тайминг импульсов, сбор данных, USB 3 | [`hardware/Zynq`](hardware/Zynq/MIRA_Zynq.kicad_pro) |
| Crossbar | Сменная плата с сокетом под конкретный кроссбар | [`hardware/Crossbar`](hardware/Crossbar/MIRA_Crossbar.kicad_pro) |
| Forming | Карта формовки до ±10 В с ограничением тока | [`hardware/Forming`](hardware/Forming/MIRA_Forming.kicad_pro) |
| Power | Карта питания: вход 24 В, промежуточные шины, супервизор, аппаратные разрешения | [`hardware/Power`](hardware/Power/MIRA_Power.kicad_pro) |

Все 64 канала одинаковы и не привязаны к роли. Плата Crossbar сама решает, какие каналы будут BL, WL или NL. Например, на место 16×16×16 можно поставить кроссбар 32×8×8.

Требования и компоновка: [техническое задание](docs/ТЗ.md) и [3D-эскиз](docs/concept-3d.html).

Общие символы, footprint и 3D-модели лежат в [`hardware/libraries`](hardware/libraries). Каждый проект подключает их через `${KIPRJMOD}/../libraries`, поэтому папку `hardware/` нужно держать целиком.

## Версии

У каждой платы своя версия. Она хранится в переменной проекта `VERSION` (Файл → Свойства проекта → Текстовые переменные) и выводится в поле Rev штампа. Изменения описаны в `CHANGELOG.md` в папке платы.

| Версия | Когда повышать |
|---|---|
| 0.0.x | Небольшие изменения |
| 0.x.0 | Большие изменения |
| 1.0.0 | Плата доделана в KiCad |

Тег версии называется по плате, например `afe-v0.1.0`. Выпуск на производство учитывается отдельно и номер версии не меняет.

## Ветки

Каждая плата разрабатывается в своей ветке `board/<плата>`. Готовые шаги вливаются в `main` через PR.
